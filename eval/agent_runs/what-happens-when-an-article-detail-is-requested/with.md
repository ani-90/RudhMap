# with get_context: what happens when an article detail is requested

A detail request is handled by `get_article_detail` in `app/api/feed.py:133-163`.

1. **Lookup.** It calls `crud.get_article` (`app/api/feed.py:135`, `app/db/crud.py:67-68`). If no row matches, it raises a 404 "Article not found".
2. **Re-scrape check.** If the stored `raw_content` is under 500 characters, or `_is_quality_content` rejects it, and the article has a URL, it calls `scraper.enrich_content` (`app/api/feed.py:142-143`). `_is_quality_content` rejects text whose average line length is under 7 words, which is how it catches navigation junk (`app/api/feed.py:123-129`).
3. **Scraping.** `enrich_content` returns the existing content if it is already long enough. Otherwise it scrapes the URL with trafilatura and truncates the result to 8000 characters (`app/services/scraper.py:28-36`).
4. **Persisting or discarding.**
   - If the scraped text is longer and passes the quality check, it replaces `raw_content` and is committed to the DB (`app/api/feed.py:144-147`).
   - If the stored content is junk and the re-scrape didn't help, `raw_content` is returned as `""` so the client shows the summary instead (`app/api/feed.py:148-150`).
5. **Response.** It returns an `ArticleDetailResponse`, which is `ArticleResponse` plus `raw_content` (`app/schemas/feed.py:37-38`). The tags are parsed from the stored JSON (`app/api/feed.py:152-162`).

**Summary not generated here:** this endpoint does not generate a summary. It returns whatever `article.summary` is stored, which may be empty. `CLAUDE.md` says this endpoint summarizes lazily, but the code doesn't. Summaries are generated by `POST /api/feed/{id}/summarize` (`app/api/feed.py:167-175`) and by quiz generation (`app/api/quiz.py:28-31`).
