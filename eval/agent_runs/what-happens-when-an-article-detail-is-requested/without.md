# without get_context: what happens when an article detail is requested

`GET /api/feed/{article_id}` is handled by `get_article_detail` (`app/api/feed.py:132`).

1. **Lookup:** it calls `crud.get_article` and returns 404 if the article doesn't exist (`feed.py:135-137`).
2. **Re-scrape check:** it re-scrapes if the stored `raw_content` is under 500 characters or fails `_is_quality_content`, and the article has a URL (`feed.py:139-142`). `_is_quality_content` is a heuristic that treats navigation-menu text as junk. It requires an average of at least 7 words per line (`feed.py:128-129`).
3. **Re-scrape result:** `scraper.enrich_content(url, raw_content)` fetches the fuller text (`feed.py:143`).
   - If the result is longer and passes the quality check, it replaces the content and is saved to the DB with `update(...)` and `commit()` (`feed.py:144-147`).
   - If the stored content is junk and the re-scrape didn't help, `raw_content` is set to `""`. The client is expected to show the summary instead (`feed.py:148-150`).
4. **Response:** it returns an `ArticleDetailResponse` with these fields (`feed.py:152-163`):
   - id, `qdrant_id`, title, URL, summary, `raw_content`
   - domain, source, tags (parsed from JSON), `fetched_at`

**Summary caveat:** this endpoint does not generate a summary. It returns `article.summary` as stored, which may be empty. That differs from CLAUDE.md, which says `GET /api/feed/{article_id}` summarizes lazily.

Summaries are generated by `POST /api/feed/{id}/summarize` (`feed.py:166-175`). That endpoint returns the cached summary if there is one. Otherwise it calls `groq_client.summarize` and saves the result.
