# Tier 2 parser output reference

This folder is a **read-only reference**, not a test suite. It shows the
actual `EvidenceRecord` (node) and `EdgeRecord` (edge) objects the Tier 2
extractor produces for its fixture input, so a reader can see the real
shape of the data without running anything.

It does not replace or duplicate the test suite under `tests/` — those
files are untouched. This is purely documentation: source fixture in, JSON
out, side by side.

Generated by parsing the fixture with the parser's public entry point and
serializing the returned `(nodes, edges)` tuple via `dataclasses.asdict`.
`EvidenceRecord` / `EdgeRecord` are defined in
[`src/rudhmap/extract/schema.py`](../../src/rudhmap/extract/schema.py).
The dangling-reference schema tier 2 commits to (import/call edge shapes,
identity scheme) is specified in
[`docs/tier2_ast_schema.md`](../tier2_ast_schema.md) — read that first if
the `attrs` shapes below look unfamiliar.

## Notes on reading the output

- `tier` is always `2` and `confidence` is always `1.0` for every record —
  unlike Tier 1's regex guesses, an AST node either exists at a location or
  it doesn't; that's a structural fact, not an inference. (Confidence
  isn't lowered for *unresolved* references either — `dst` being dangling
  reflects incomplete *information*, not doubt about what the AST says.)
- `file` paths are recorded exactly as returned by the parser on the
  machine that generated this doc (Windows-style backslashes).
- Every edge's `src`/`dst` is scoped to the single file being parsed. A
  bare file path (no `:qualname` suffix) as `src` means the statement sits
  at module level, outside any function or class body. `dst` on every edge
  here is an **unresolved string** — see "Why every edge is dangling"
  in `python.md`.
